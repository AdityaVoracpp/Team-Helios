## Theme

- **LOCKED:** Intelligent IT Ticket Analysis and Resolution Assistant (Enterprise IT / Service Management). Analyze incoming tickets, identify similar historical cases, recommend evidence-backed resolutions, provide deflection & confidence fallbacks, and capture feedback/audit trails (FR-01 to FR-08).

## Judging

Four criteria, no weights published:

| Criterion | Notes | Implied weight |
| --- | --- | --- |
| Technical Execution | "Proper implementation of the stack" — use the stack correctly, not cleverly | 25% (assumed equal) |
| Innovation & Impact | How unique and practical | 25% (assumed equal) |
| User Experience | UI/UX quality and usability — a quarter of the score is how it looks and feels | 25% (assumed equal) |
| Functionality | How well the project works | 25% (assumed equal) |

Confirm weights on the day. If equal, UX is not a finishing touch — it is 25% of the score and must be built in, not added at the end.

## Submission requirements

- GitHub repository with a README. **Required.**
- Live deployment link. **Optional** (but cheap, early, and supports Technical Execution).
- A short pitch explaining the solution. **Required.**

## Sprint structure

| Sprint | Time | Goal | Deliverable |
| --- | --- | --- | --- |
| 0 | First 1-1.5h | Ideation, setup, strategy | Roadmap and approach, all in the repo README |
| 1 | Next 3-4h | Core functionality | Working prototype, core features integrated; midpoint check-in with Chapter Members |
| 2 | Final 1h | Refinement, testing, submission, demo | Functional MVP with clear documentation |

## Expectations

- Teams work in parallel: backend and frontend simultaneously.
- Code must be clean, modular, well-documented.
- Midpoint check-in with Chapter Members for feedback during Sprint 1.

## Technical constraints

- Stack named in brief: React frontend, backend API (CRUD, optional auth, optional DB), database transactions.
- Deployment "good to have": AWS, Vercel, or similar.
- No prohibited tools, APIs, or license terms stated.
- No provided credits or keys stated — verify your own before the day.

None stated in the brief.
